# Phase 3 - System Status, Empty States, and Recovery UX

---

# Objective

Plan how the UI communicates backend readiness and failure clearly.

---

# STEP 3.5.1 - Define system status view

Recommended status items:

* API status
* database status
* LLM status
* data provider status

---

# STEP 3.5.2 - Define empty states

Needed empty states:

* before first analysis
* no suggestions returned
* detail page without data

---

# STEP 3.5.3 - Define recovery actions

Users should be able to:

* retry request
* edit symbols
* reduce lookback days if needed
* go back to dashboard

---

# Completion Checklist

* [ ] system status area planned
* [ ] empty states listed
* [ ] recovery actions defined
