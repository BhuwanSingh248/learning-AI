# 📘 Phase 2 — Closure & Model Benchmarking Report

## Objective

Review and close Phase 2 of the Stock Recommendation Agent. All 8 core tasks (from STEP 2.1 to STEP 2.8) have been fully implemented, tested, and validated.

---

## 🎯 Completed Steps Summary

### 1. Metrics & Observability (`src/metrics/`)
* Exposed latency metrics directly in API response structures under `/analyze`.
* Tracks step-by-step latency for **Retrieval**, **Reranking**, **Grounding**, **Prompt Building**, and **LLM Generation**.

### 2. Prompt Abstraction & Versioning (`src/llm/`)
* Created robust typing models (`RecommendationPrompt`, `PromptPayload`) to formalize inputs.
* Externalized base system prompts into version-controlled files (`prompts/system_v1.txt`).
* Implemented structured response parsers parsing LLM decisions (BUY/SELL/HOLD), confidence scores, and citation indices.

### 3. Multi-Query Expansion & Search Deduplication
* Connected semantic query expansion logic to broaden retrieval candidates.
* Merges and deduplicates chunks from semantic (FAISS) and keyword (BM25) lookups to optimize context quality.

### 4. Neural Reranking
* Fully integrated `cross-encoder/ms-marco-MiniLM-L-6-v2` reranker, providing high-fidelity logit relevancy scores for retrieved evidence.

### 5. Citation & Source Attribution
* Created clean, gapless document citation brackets (e.g. `[1]`, `[2]`) referencing publications, dates, and metadata returned in the API output.

### 6. End-to-End Test Verification
* Added parameterized test coverage across 20+ test scenarios (`tests/e2e/test_pipeline_e2e.py`). All pipeline paths are verified.

### 7. Golden Evaluation Dataset & Evaluation Engine
* Compiled 60 diverse, structured queries (`evaluation/evaluation_dataset.json`) representing real-world user intent, refusal, and safety checks.
* Developed metrics reporting logic in `run_evaluation.py`, producing precision, recall, and grounding metrics.

### 8. Model Benchmarking Framework
* Integrated supported model registries (`src/llm/model_registry.py`) and provider abstractions (`src/llm/providers/`).
* Created `run_benchmark.py` and `model_ranking.py` compiling overall model suitabilities.

## 🐞 Phase 2 Closure Backlog & Bug Fixes

We have resolved all 15 bugs/functional gaps (Bugs 2.9.1 to 2.9.15) identified in the Phase 2 Closure Backlog:

1. **Bug 2.9.1 — Intent Routing:** Added keyword-based query intent router (`src/query_router/`) bypassing RAG for `FUNDAMENTAL` queries to avoid false retrievals.
2. **Bug 2.9.2 — Grounding Threshold Calibration:** Calibrated default thresholds to `-7.0` (peak) and `-10.5` (average) in settings and `.env` for balanced grounding gate decisions.
3. **Bug 2.9.3 — Empty Symbol Diagnostics:** Added detailed `failure_type` metadata to failures (e.g. `NO_NEWS_INDEXED`, `NO_RELEVANT_EVIDENCE`, `WEAK_EVIDENCE_QUALITY`, `RETRIEVAL_FAILED`).
4. **Bug 2.9.4 — Supported Capability Metadata:** Implemented `GET /capabilities` returning supported and unsupported features.
5. **Bug 2.9.5 — Model Metadata Endpoint:** Implemented `GET /models` exposing active reasoning models.
6. **Bug 2.9.6 — Pipeline Status Endpoint:** Implemented `GET /pipeline/status` checking connectivity of FAISS, DB, reranker, and Ollama.
7. **Bug 2.9.7 — Evaluation Dataset Coverage:** Expanded the golden evaluation dataset in `evaluation_dataset.json` to 102 cases covering positive/negative/risk news, refusal, and historical queries.
8. **Bug 2.9.8 — Benchmark Runner Validation:** Verified execution paths for Mistral, Qwen, Llama, and Phi4 in `run_benchmark.py` under simulated and real environments.
9. **Bug 2.9.9 — Historical Events Validation:** Marked `historical_events.json` as a seed dataset and created `data/historical_events_readme.md`.
10. **Bug 2.9.10 — Historical Similarity Evaluation:** Added unit tests validating similarity-based semantic lookups (e.g., `Russia-Ukraine War`) in `tests/history/test_history.py`.
11. **Bug 2.9.11 — Missing Visualization Endpoints:** Added `GET /evaluation/results`, `GET /benchmark/results`, `POST /historical-events/search`, and `POST /signals` to enable UI representation.
12. **Bug 2.9.12 — Recommendation Explainability:** Exposed aggregated signals, historical matches, and citations in the JSON response model of the `/analyze` endpoint.
13. **Bug 2.9.13 — News Freshness Monitoring:** Implemented freshness check in `/health` alerting if no news articles have been indexed in the last 24 hours.
14. **Bug 2.9.14 — Duplicate Indexing Protection:** Implemented MD5 checksum verification in `NewsIndexer` against existing db items to prevent redundant chunks in the vector/relational databases.
15. **Bug 2.9.15 — RAG Observability:** Integrated a new relational database table `rag_pipeline_metrics` (via `MetricRecord`) storing and persisting pipeline latency and grounding statistics.
